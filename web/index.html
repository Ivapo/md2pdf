What this adds to markdown

Twenty-two constructs are supported and ten are shown here — the ones a reader cannot get from an ordinary markdown renderer. The README is the complete reference. Each row is the same source read two ways: what md2pdf makes of it, and what a renderer with no notion of the construct makes of it.

1 · Syntax an ordinary renderer passes through as text

The marker means something here and nothing anywhere else, so the difference is on the page without a PDF: the other column prints it. Captions · Groups · Names

A paragraph opening : beneath a table, an image or a code block is that block's caption.

The same marker under a code block

One mechanism over three constructs, each counting on its own — so inserting a table above a listing does not renumber the listing.

an ordinary renderer

A code block, and then a paragraph reading : The entry point. beneath it.

Listing 1, captioned beneath and set to the left edge, because code is read from where its lines begin.

A pair of ::: lines makes several blocks one figure

The members share one caption, one number and one name. No arrangement of the : marker alone can say that.

md2pdf
an ordinary renderer

Two separate tables, with ::: printed as a paragraph above and below them, and the caption line as a third paragraph.

One Table 1 with both members side by side, taking a single number between them.

Name a figure, and point at it

End a caption with {#name}, then write [](#name) — a link with nothing between the brackets — to refer to it.

md2pdf
an ordinary renderer

The {#tab:m} printed at the end of the caption paragraph, and a sentence with a gap in it: [](#tab:m) is a link whose text is empty, so there is nothing to show.

“As Table 1 shows…”, and it stays true — insert another table above it and the sentence reads Table 2 without your touching it.

Math is LaTeX, and it is checked before it is set

2 · Things markdown has no way to say

These are not markers a renderer misses. They are decisions about a printed page, and a page is what markdown has never had. Frontmatter · Footnotes

3 · What it refuses, on purpose

A showcase that hides its refusals is selling something. Dropping or flattening content would ship a PDF that lies about its source, so the compiler names what it cannot handle and its line — and these are the sentences it prints, checked against the compiler by the same test that compiles every example above.
